## 🛠️ 二、 本地开发与调试指南

如果您需要在本地对管理后台的前端页面（如 UI 修改、报表增加等）进行二次开发，请按以下步骤运行：

1. **进入前端项目目录**：
   ```bash
   cd D:\Trae\PcGetPic\admin-panel
   ```
2. **安装依赖包**：
   ```bash
   npm install
   ```
3. **启动本地开发热更新服务器**：
   ```bash
   npm run dev
   ```
   * 开发服务默认将运行在本地的 `http://localhost:5174`（或控制台提示的其他可用端口）。
4. **接口反向代理机制**：
   * 本项目的 Vite 配置文件（`vite.config.ts`）中配置了开发代理。在本地开发模式下，前端对 `/api` 的所有网络请求都会自动被转发到本地的 Node.js 后端服务 `http://localhost:3001` 上，以避免跨域问题。

## 📦 三、 生产环境编译与发布规范

当管理后台开发完成，或者需要更新线上页面时，请进行静态打包：

1. **在本地前端目录执行编译构建**：
   ```bash
   npm run build
   ```
   * 编译完成后，项目根目录下会生成一个名为 `dist/` 的文件夹（内含高度压缩的 `index.html`、`assets` 静态资源文件）。
2. **上传部署到宝塔服务器**：
   * 将本地生成的 `dist/` 文件夹中的 **全部内容**，通过宝塔文件管理器上传覆盖至以下目录：
     `/www/wwwroot/admin.downpictures.com/`
3. **线上管理后台访问 URL**：
   * 部署完成后，可通过公网域名安全访问：`https://admin.downpictures.com`

## 四、统计页面性能开发约束（修改前必读）

管理后台统计页的“快”来自前后端共同约定，后续开发不能只看接口功能正确：

1. **正常访问不要强制刷新缓存**
   * 首次进入页面、路由切换、日期范围切换均使用普通 GET。
   * 只有用户主动点击“刷新”按钮时才传 `fresh=1`。
   * `fresh=1` 会触发后端真实重算；如果每个请求都带它，30/60 秒短缓存将完全失效。

2. **摘要先显示，图表渐进加载**
   * 统计页先请求 summary，让核心数字尽快出现。
   * 图表接口随后并发，各自返回后立即更新各自区域。
   * 不要恢复成一个大 `Promise.all` 成功后才一次性显示，否则整页会被最慢接口拖住。

3. **必须防止旧请求覆盖新请求**
   * 日期范围快速切换、分页和搜索都可能产生并发响应。
   * 保留 `latestRequestId`（或等价的取消请求机制），只允许最新请求修改页面状态。

4. **发布必须使用生产构建**
   * 执行 `npm run build` 后只部署 `dist/`。
   * 不要把 Vite 开发服务作为线上服务；Nginx 应开启 gzip 和带哈希静态资源长缓存。

5. **修改统计页后的最低验证**
   * 连续快速切换日期范围，最终数据必须与最后一次选择一致。
   * 点击“刷新”应发送 `fresh=1`；普通进入页面不应携带该参数。
   * 一个图表接口失败时，已成功的摘要和其他图表仍应正常显示。
   * 执行 `npm run build`，确保 TypeScript 与生产打包通过。
