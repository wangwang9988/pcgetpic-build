## 评审「当图 store + 图个吉利 buy 国际化 & Stripe 港币支付」实施方案

评审对象：`C:\Users\xiang\.gemini\antigravity\brain\53ad1582-.../implementation_plan.md`（同事产出），已核对 `server/` 实际代码后给出建设性意见，输出一段可直接转发的评审文字（未落文件）。

核对到的关键事实（后续同类改造可复用）：
- server 用 **SQLite + better-sqlite3**（`db.transaction(...).immediate()`），不是 MySQL；`DECIMAL(10,2)` 实际按 REAL 存。
- `ORDER_EXPIRE_MS = 30min`（constants.ts:168），而 Stripe Checkout Session 默认 24h 有效 → 过期订单收到 paid webhook 会抛 `ORDER_NOT_PENDING`，是"钱收了码没发"的高危缺口。
- order_no 规则：`PCGP` + 13 位毫秒时间戳 + 6 位随机（约 31 bit 熵）；`GET /payment/order-status` 无鉴权且已返回激活码 → 方案再往里加 `email` 属 PII 泄露，建议改用 success_url 的 `{CHECKOUT_SESSION_ID}` 反查。
- dashboard 营收用 `SUM(orders.amount)`；方案让 amount 保持人民币口径会把 HK$ 订单按 ¥ 累加，口径实际是错的。
- 已有 `ORDER_RECONCILE_MIN_INTERVAL_MS = 2500` 节流（支付宝对账），Stripe 侧需同样节流。
- 退款只有 `refunded_at` + 后台人工标记，无真实退款 API 调用。

外部核实：Stripe HKD 最低收款 4.00；香港费率 3.4% + HK$2.35，国际卡 +0.5%（合计 3.9%）；币种换算另收 2%。据此 HK$15 体验包手续费占比 19.6%，HK$49 占 8.7%。

结论建议：拆成 i18n / Stripe 两个里程碑；先补资金正确性五条（订单过期 vs Session 生命周期、双通道重复收款、退款链路、webhook 幂等落 DB 唯一索引、财务双口径），再重做港币定价公式（当前八个套餐溢价率 6%~39%，隐含折算率 0.66~0.87，不成体系）。
